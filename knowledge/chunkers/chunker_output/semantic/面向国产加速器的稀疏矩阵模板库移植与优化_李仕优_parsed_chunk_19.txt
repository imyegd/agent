# 2.2 数据访问模块适配

数据访问模块负责从国产加速器的存储体中获取计算所需的数据，其包含全局内存数据访问和共享内存数据访问两部分。全局内存数据访问负责从全局内存中读取参与计算的数据；共享内存数据访问负责将共享内存作为中间桥梁，暂存从全局内存中读取的数据，以满足数据复用和后续 Tensor Core计算所需的数据排布要求。数据访问模块适配的核心挑战在于访存模式与硬件指令集的差异性重构。

移植实现如图 6 所示，在步骤一中，根据线程号计算出各线程访问稀疏矩阵值和列块索引数据的

全局内存读索引及共享内存写索引，将值和列块索引数据写入共享内存；在步骤二中，根据线程号和列块索引数组计算出各线程访问稠密矩阵数据的全局内存读索引及共享内存写索引，将稠密矩阵数据写入共享内存；在步骤三中，根据线程号计算出各线程访问共享内存数据的读索引，将共享内存数据加载到寄存器中供后续 Tensor Core 计算。上述步骤中，使用国产加速器的 builtin 接口（编译器提供的硬件指令的 $\mathrm { C } { + + }$ 接口）和内嵌汇编指令取代 NVIDIAPTX 指令完成共享内存数据的读写操作。

# 2.3 数据计算模块与结果写回模块适配

数据计算模块负责利用Tensor Core对数据访问模块中所获取的数据执行计算操作，结果写回模块则是负责将数据计算模块的计算结果写回全局内存。由于硬件架构的差异，NVIDIA GPU 与国产加速器在使用Tensor Core计算时所需的数据排布要求和指令不同，计算完成后各线程将计算结果写回全局内存的位置索引也不同。在图 6 所示的移植实现的步骤四中，线程读取寄存器中预加载的数据，整个线程束读取的数据组成国产加速器Tensor Core计算所需的数据排布，使用国产加速器 builtin 接口调用 Tensor Core 硬件完成数据计算。在步骤五中，根据线程号计算出各线程写回全局内存的目标地址，将计算结果写回全局内存。最后，经过正确性验证，CUTLASS-Sparse 与 CPU 验证程序的误差在精度范围内，CUTLASS-Sparse 可以在国产加速器上正确运行，完成移植工作。

本文提出的移植方案适用于本研究所面向的某系列深度学习加速器，对于其他系列的深度学习加速器，需要根据其硬件特性对硬件指令相关模版和

数据读写索引等方面进行针对性修改，才能完成适配工作。本文的移植方案兼容了原 CUTLASS-Sparse

库中的设备层接口，因此对于使用者而言，仍然保证了模板库接口的灵活性。
