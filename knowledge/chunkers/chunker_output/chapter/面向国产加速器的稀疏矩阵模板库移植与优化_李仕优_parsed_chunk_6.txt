# 1.2 SpMM 相关研究

在 SpMM算法层面，Yang 等人[7]基于压缩稀疏行（CSR）稀疏矩阵存储格式[19]提出了基于行划分和基于合并的 SpMM 算法；Huang 等人[8]对基于行划分的 SpMM 算法进一步优化，引入共享内存以实现稀疏矩阵数据的复用，提高了全局内存数据的访问效率；Nagasaka 等人[9]提出了一种批量 SpMM 算法，在单个通用计算核心上处理多个 SpMM 运算，充分利用 GPU 的高并行性。以上方法虽然能基于通用计算核心方式有效利用稀疏矩阵的数据规律，但其共同局限性是未能利用Tensor Core带来的显著算力优势。针对此局限性， $\mathbf { W } \mathbf { u } ^ { [ 2 0 ] }$ 提出 Tensor Core（负责处理密集计算）与通用计算核心（负责数据管理和稀疏边缘处理）相结合的策略；Han 等人[21]基于CSR 格式将向量-向量点乘运算转换为矩阵-矩阵乘法，使得高效压缩的 CSR 格式能够符合 Tensor Core

计算所需的数据排布要求；Li 等人[14]提出了一种新的存储格式 SR-BCRS（Strided Row-major BlockCompressed Row Storage），该存储格式可以将低精度整数数据进行压缩，使得低精度整数数据的排布符合 Tensor Core 计算的数据排布要求，实现了一种低精度整数 SpMM 算法；Okanovic 等人[13]通过将块压缩稀疏行（BCSR）稀疏矩阵存储格式[22]的相似的行聚集在一起来显著减少 Tensor Core 计算块的数量，并利用异步数据加载等方法进一步提升算法的性能；Zhao 等人[6]通过数据相似性重排序和负载均衡等方法来优化基于 Tensor Core 的 SpMM 算法。

在 SpMM 数学库层面，国产加速器平台的SPARSE 数学库仅支持基于通用计算核心方式的SpMM 算法，未能支持 Tensor Core 参与计算；而NVIDIA 推出的 cuSPARSE 和 cuSPARSELt 提供了基于 Tensor Core 的 SpMM 算法，其中 cuSPARSELt要求稀疏矩阵的数据排布规律遵循 2:4 稀疏模式。

上述基于 Tensor Core 的 SpMM 算法和数学库虽然充分发挥了并行处理器的性能，但又普遍存在定制化程度不足的问题。针对此问题，NVIDIA 推出的 CUTLASS-Sparse 是一款基于 Tensor Core 的SpMM 模版库，在确保高性能的前提下兼顾程序的可定制化。
