# 面向国产加速器的稀疏矩阵模板库移植与优化

李仕优 1，廉德萌 2，周鑫 2，韩孟之 2*

(1.郑州大学，计算机与人工智能学院，郑州 450000；2.曙光信息产业（北京）有限公司，北京 100193)

摘 要：CUDA线性代数模板库（CUTLASS）中的CUDA稀疏矩阵模版库（CUTLASS-Sparse）用于构建可定制化且高性能的稀疏矩阵-稠密矩阵乘法（SpMM）内核，其在科学计算、深度学习等众多领域发挥着重要作用。但其仅针对NVIDIA GPU进行实现和优化，并不能应用于国产加速器。为了解决该问题，提出 CUTLASS-Sparse 面向国产加速器的移植与优化方案。在移植阶段，针对国产加速器硬件架构对数据访问模块、数据计算模块和数据写回模块进行适配。在优化阶段，针对其中存在的共享内存物理存储体（bank）冲突率高且共享内存带宽利用率低、数据流水线并行度低和数据写回效率低的问题，提出两种共享内存数据重排算法、基于数据预取与寄存器双缓冲的数据流水线策略和基于数据聚集的数据写回策略。实验结果表明，三种优化方法均显著提升了移植后的 CUTLASS-Sparse 的性能。对于 TF32 和 FP16 数据类型，经过优化后的CUTLASS-Sparse的整体性能相较于优化前分别平均提升了 $3 0 \%$ 和 $1 1 5 \%$ ，分别平均达到 NVIDIA GPU L20 上 CUTLASS-Sparse性能的 $7 6 \%$ 和 $6 0 \%$ 。在两种硬件版本下，移植与优化后的CUTLASS-Sparse性能分别平均为国产加速器平台的SPARSE数学库性能的2.36倍和3.09倍。实验结果验证了移植与优化方案的有效性。

关键词：稀疏矩阵；CUDA 线性代数模板库；稀疏矩阵稠密矩阵乘法；国产加速器；移植与优化；张量核心

# Transplantation and Optimization of Sparse Matrix Template Library for Domestic Accelerators

Li Shiyou1, Lian Demeng2, Zhou Xin2, Han Mengzhi2*

(1. School of Computer and Artificial Intelligence, Zhengzhou University, Zhengzhou 450000, Henan, China;

2. Dawning Information Industry (Beijing) Co., Ltd., Beijing 100193, China)

【Abstract】The CUDA sparse matrix template library (CUTLASS-Sparse) in the CUDA linear algebra template library (CUTLASS) is used to build customizable and high-performance sparse matrix-dense matrix multiplication (SpMM) kernels, which play an important role in many fields such as scientific computing and deep learning. However, it is only implemented and optimized for NVIDIA GPUs and cannot be applied to domestic accelerators. To solve this problem, a transplantation and optimization scheme for CUTLASS-Sparse for domestic accelerators is proposed. In the transplantation stage, the data access module, data computation module and data write-back module are adapted to the hardware architecture of domestic accelerators. In the optimization stage, two shared memory data reordering algorithms, a data pipeline strategy based on data prefetching and register double buffering, and a data write-back strategy based on data aggregation are proposed to address the problems of high conflict rate of shared memory physical storage units (bank), low shared memory bandwidth utilization, low data pipeline parallelism and low data write-back efficiency. Experimental results show that all three optimization methods significantly improve the performance of the transplanted CUTLASS-Sparse. For TF32 and FP16 data types, the overall performance of the optimized CUTLASS-Sparse increases by an average of $3 0 \%$ and $1 1 5 \%$ compared to the unoptimized version, respectively. It reaches an average of $7 6 \%$ and $6 0 \%$ of the performance of CUTLASS-Sparse on NVIDIA GPU L20, respectively. Under two hardware versions, the performance of the transplanted and optimized CUTLASS-Sparse is on average 2.36 times and 3.09 times that of the SPARSE math library on domestic accelerator platforms, respectively. The experimental results verify the effectiveness of the transplantation and optimization scheme.

【Key words】sparse matrix; CUTLASS; SpMM; domestic accelerator; transplantation and optimization; tensor core

# 0 引言

稀疏矩阵-稠密矩阵乘法（SpMM）是图神经网络[1-2]、推荐系统[3]、大规模深度学习模型[4]和线性代数求解器[5]等领域的关键计算内核，其计算效率

对于相关应用的性能表现至关重要。CUDA 线性代数模板库（CUTLASS）是一个 CUDA $\mathrm { C } { + } { + }$ 模板抽象的集合，为通用矩阵乘法（GEMM）、稀疏矩阵-稠密矩阵乘法（SpMM）及卷积算子（Convolution）

提供了可定制化且高性能的实现。CUDA 稀疏矩阵模板库（CUTLASS-Sparse）是 CUTLASS 中的 SpMM模块，其灵活高效的实现为 SpMM 相关领域的应用加速提供了有效解决方案。

目前，对 SpMM 的算法和数学库的研究已经非常广泛。业界已经利用多种技术来优化 SpMM算法的性能，包括稀疏存储格式、稀疏矩阵数据重排序算法、并行策略和内存访问优化等[6]。由于稀疏矩阵数据排布的不规则性，相比目前先进的张量核心（Tensor Core），基于传统的通用计算核心（如CUDA 核心等）方式设计的 SpMM 算法能够更好地适应稀疏矩阵的数据排布规律[7-9]，但基于通用计算核心设计的 SpMM 算法并没有充分发挥 GPU 等并行处理器的硬件优势。研究表明，稀疏矩阵存储格式的更新对于提高 SpMM 的性能是有效的[10-12]，因此业界更倾向于研究如何转变稀疏存储格式从而更好地利用 Tensor Core 的算力[6，13-14]。在 SpMM 数学库方面，常见的 SpMM 数学库包括 cuSPARSE[15]、cuSPARSELt[16]、CUTLASS-Sparse[17]和国产加速器平台 SPARSE 数学库等。当前大部分 SpMM 算法和数学库普遍存在定制化程度不足或性能不佳的问题，仅 CUTLASS-Sparse 不仅能够支持研究人员定制化设计 SpMM 的计算流程[18]，同时具有高性能的优势。

尽管 SpMM 在 NVIDIA GPU 上已有较多实现，但面向国产加速器的研究仍显不足。在国产加速器中现有方案为 SPARSE 数学库，但其存在两大局限：其一，其计算模式依赖通用计算核心，无法利用国产加速器新一代先进 Tensor Core 带来的性能优势；

其二，其作为封闭式接口库，计算流程固化，开发者无法灵活定制 SpMM 计算流程。因此，国产加速器上缺乏一款用于支持稀疏矩阵与稠密矩阵乘法运算的可定制化且高性能的模版库。

为了解决该问题，将 CUTLASS-Sparse 移植到国产加速器上，并根据国产加速器的硬件特性进行优化，能够弥补国产加速器上可定制化且高性能的SpMM 模板库的缺失，进一步完善国产加速器的软件生态。本文的主要贡献如下：

（1）将 CUTLASS-Sparse 从 NVIDIA GPU 平台移植至国产加速器平台；  
（2）针对稀疏矩阵和稠密矩阵，设计两种共享内存数据重排算法，解决了读和写共享内存的 bank冲突问题，充分利用了共享内存带宽；  
（3）针对 CUTLASS-Sparse 中的数据流水线，设计一种基于数据预取与寄存器双缓冲的数据流水线策略，提升了数据流水线的并行度与性能；  
（4）针对CUTLASS-Sparse中的数据写回阶段，设计一种基于数据聚集的数据写回策略，提高了全局内存的带宽利用率，从而提升数据写回的性能。

# 1.2 SpMM 相关研究

在 SpMM算法层面，Yang 等人[7]基于压缩稀疏行（CSR）稀疏矩阵存储格式[19]提出了基于行划分和基于合并的 SpMM 算法；Huang 等人[8]对基于行划分的 SpMM 算法进一步优化，引入共享内存以实现稀疏矩阵数据的复用，提高了全局内存数据的访问效率；Nagasaka 等人[9]提出了一种批量 SpMM 算法，在单个通用计算核心上处理多个 SpMM 运算，充分利用 GPU 的高并行性。以上方法虽然能基于通用计算核心方式有效利用稀疏矩阵的数据规律，但其共同局限性是未能利用Tensor Core带来的显著算力优势。针对此局限性， $\mathbf { W } \mathbf { u } ^ { [ 2 0 ] }$ 提出 Tensor Core（负责处理密集计算）与通用计算核心（负责数据管理和稀疏边缘处理）相结合的策略；Han 等人[21]基于CSR 格式将向量-向量点乘运算转换为矩阵-矩阵乘法，使得高效压缩的 CSR 格式能够符合 Tensor Core

计算所需的数据排布要求；Li 等人[14]提出了一种新的存储格式 SR-BCRS（Strided Row-major BlockCompressed Row Storage），该存储格式可以将低精度整数数据进行压缩，使得低精度整数数据的排布符合 Tensor Core 计算的数据排布要求，实现了一种低精度整数 SpMM 算法；Okanovic 等人[13]通过将块压缩稀疏行（BCSR）稀疏矩阵存储格式[22]的相似的行聚集在一起来显著减少 Tensor Core 计算块的数量，并利用异步数据加载等方法进一步提升算法的性能；Zhao 等人[6]通过数据相似性重排序和负载均衡等方法来优化基于 Tensor Core 的 SpMM 算法。

在 SpMM 数学库层面，国产加速器平台的SPARSE 数学库仅支持基于通用计算核心方式的SpMM 算法，未能支持 Tensor Core 参与计算；而NVIDIA 推出的 cuSPARSE 和 cuSPARSELt 提供了基于 Tensor Core 的 SpMM 算法，其中 cuSPARSELt要求稀疏矩阵的数据排布规律遵循 2:4 稀疏模式。

上述基于 Tensor Core 的 SpMM 算法和数学库虽然充分发挥了并行处理器的性能，但又普遍存在定制化程度不足的问题。针对此问题，NVIDIA 推出的 CUTLASS-Sparse 是一款基于 Tensor Core 的SpMM 模版库，在确保高性能的前提下兼顾程序的可定制化。

# 1.3 Blocked-ELL 稀疏矩阵存储格式

常见的稀疏矩阵存储格式有压缩稀疏行/压缩稀疏列（CSR/CSC）[19]、坐标格式（COO）[23]和块压缩稀疏行（BCSR）等，这些存储格式中的非零元素在行或列维度呈现非均匀分布，导致并行计算时访存不规则。因此，这些存储格式并不能充分发挥并行处理器的性能优势。

Blocked-ELL（Blocked-Ellpack）稀疏矩阵存储格式[24]是 ELL（Ellpack）稀疏矩阵存储格式[25]的扩展。Blocked-ELL 稀疏矩阵存储格式如图 2 所示，其共包含三个部分：值数组、列块索引数组和分块大小。分块大小定义了数据存储的基本单位，值数组用于存储包含非零元素的分块的数据，列块索引数组用于存储每行中分块的列索引（空余位置用-1填充）。

![](images/d22c6a76607e0ebed3c6ea92be1dfd8f2040840bd52b86dfa1bababad4a094f4.jpg)  
图 2 Blocked-ELL 稀疏矩阵存储格式  
Fig.2 The Blocked-ELL storage format of sparse matrix

Blocked-ELL 稀疏矩阵存储格式相较于常见的稀疏矩阵存储格式具有规整的访存模式和较低的线程束分支分歧，更适合发挥并行处理器性能优势[25]。

# 1.4 CUTLASS-Sparse

CUTLASS-Sparse实现了一种基于Blocked-ELL稀疏矩阵存储格式的 SpMM 算法（B-SpMM）。图 3展示了 B-SpMM 的计算过程，给定稀疏矩阵值数组（Blocked-ELL 格式的分块大小设定为 2）、列块索引数组和稠密矩阵，对矩阵进行划分矩阵分块（大小为 $2 \times 2 ^ { \cdot }$ ），K 方向作为 B-SpMM 的累加维度。在B-SpMM 的计算过程中，线程块沿着累加维度迭代遍历所有的矩阵分块，利用 Tensor Core 完成矩阵分块的乘累加计算，迭代遍历过程中结合列块索引数组跳过白色方格所表示的不需要参与计算的数据。累加维度遍历完成后得到的累加结果为输出矩阵的一个子矩阵，所有线程块遍历累加维度结束后得到

完整的输出矩阵。

# 2.1 移植流程

CUTLASS-Sparse 的移植流程如图 5 所示。移植流程共分为四个阶段：在第一阶段，使用国产加速器平台的运行时（runtime）接口替换 NVIDIA 平台的运行时接口，并且由于国产加速器与 NVIDIAGPU 硬件架构的区别，需要将线程束（warp）大小

调整为国产加速器中线程调度的最小单位 64；在第二和第三阶段，实现数据访问模块、数据计算模块和 结 果 写 回 模 块 的 适 配 ， 这 些 模 块 的 适 配 是CUTLASS-Sparse 移植工作的重点，下文将重点介绍这些模块的适配工作；在第四阶段，将移植后的CUTLASS-Sparse 与 CPU 验证程序进行结果对比，若误差在精度范围内，则正确性验证通过，完成移植工作。

# 2.2 数据访问模块适配

数据访问模块负责从国产加速器的存储体中获取计算所需的数据，其包含全局内存数据访问和共享内存数据访问两部分。全局内存数据访问负责从全局内存中读取参与计算的数据；共享内存数据访问负责将共享内存作为中间桥梁，暂存从全局内存中读取的数据，以满足数据复用和后续 Tensor Core计算所需的数据排布要求。数据访问模块适配的核心挑战在于访存模式与硬件指令集的差异性重构。

移植实现如图 6 所示，在步骤一中，根据线程号计算出各线程访问稀疏矩阵值和列块索引数据的

全局内存读索引及共享内存写索引，将值和列块索引数据写入共享内存；在步骤二中，根据线程号和列块索引数组计算出各线程访问稠密矩阵数据的全局内存读索引及共享内存写索引，将稠密矩阵数据写入共享内存；在步骤三中，根据线程号计算出各线程访问共享内存数据的读索引，将共享内存数据加载到寄存器中供后续 Tensor Core 计算。上述步骤中，使用国产加速器的 builtin 接口（编译器提供的硬件指令的 $\mathrm { C } { + + }$ 接口）和内嵌汇编指令取代 NVIDIAPTX 指令完成共享内存数据的读写操作。

# 2.3 数据计算模块与结果写回模块适配

数据计算模块负责利用Tensor Core对数据访问模块中所获取的数据执行计算操作，结果写回模块则是负责将数据计算模块的计算结果写回全局内存。由于硬件架构的差异，NVIDIA GPU 与国产加速器在使用Tensor Core计算时所需的数据排布要求和指令不同，计算完成后各线程将计算结果写回全局内存的位置索引也不同。在图 6 所示的移植实现的步骤四中，线程读取寄存器中预加载的数据，整个线程束读取的数据组成国产加速器Tensor Core计算所需的数据排布，使用国产加速器 builtin 接口调用 Tensor Core 硬件完成数据计算。在步骤五中，根据线程号计算出各线程写回全局内存的目标地址，将计算结果写回全局内存。最后，经过正确性验证，CUTLASS-Sparse 与 CPU 验证程序的误差在精度范围内，CUTLASS-Sparse 可以在国产加速器上正确运行，完成移植工作。

本文提出的移植方案适用于本研究所面向的某系列深度学习加速器，对于其他系列的深度学习加速器，需要根据其硬件特性对硬件指令相关模版和

数据读写索引等方面进行针对性修改，才能完成适配工作。本文的移植方案兼容了原 CUTLASS-Sparse

库中的设备层接口，因此对于使用者而言，仍然保证了模板库接口的灵活性。

# 3 CUTLASS-Sparse 的优化

# 3.1 共享内存数据重排算法

图 3 展示了 CUTLASS-Sparse 中数据排布的规定，对于稀疏矩阵（值数组）和稠密矩阵，若其数据沿 K或 M/N方向连续，则称为 K或 M/N 主序矩阵，相应地，提出了 K主序和 M/N主序共享内存数据重排算法。两种共享内存数据重排算法覆盖了CUTLASS-Sparse 中所有可能的数据主序场景。

共享内存是国产加速器的一个关键存储部件，可以被同一线程块中的所有线程访问，相较于全局内存其具有更低的访问延迟[26]。在国产加速器中，共享内存由 32 个独立的物理存储体（bank）组成，每个 bank 具有多个 4 字节（B）存储单元，单个 bank在一个时钟周期内完成一次 4B 数据的读或写操作，

32 个 bank 能够并行实现数据访问，因此共享内存的一次内存事务最多可以实现 128B 数据的访问。当同一线程束中的不同线程在同一时钟周期内访问同一bank 内的不同存储单元时，会发生 bank 冲突，此时对一个 bank 的访问请求会被串行执行，严重影响共享内存的访问效率；将一个线程束划分为若干个线程束子集（线程束子集中线程号连续），若各个线程束子集访问共享内存的数据量为一次共享内存事务所能访问的最大数据量（128B）且访问的数据能够覆盖 32 个 bank，则不会发生 bank 冲突。

移植后的 CUTLASS-Sparse 存在 bank 冲突问题；并且对于 K 主序矩阵，为满足后续 Tensor Core计算所需的数据排布要求，在写入共享内存时会将K 方向连续的数据写入共享内存非连续的跨距方

向，引发大量共享内存写指令发射，造成共享内存带宽利用率不足。本文以线程束为研究单位进行算法描述，数据类型选用 FP16 类型。

# 3.1.1 K 主序共享内存数据重排算法

图 7 展示了 K 主序共享内存数据重排算法的示意图，其中 b 表示 bank 编号，数字序号表示连续的4 个 FP16 数据，T 表示线程号，各个方格（覆盖 2个连续 bank）表示线程从共享内存中读取对应 4 个FP16 数据或写入对应 4 个 FP16 数据至共享内存。

首先解决读共享内存的 bank 冲突问题。线程束中的每个线程需要从共享内存中读取4个FP16（8B）数据去参与 Tensor Core 计算，因此连续的 16 个线

程读取的数据量为共享内存一次内存事务的最大数据量（128B）。图 7 中（a）展示了读共享内存时数据与线程的排布情况，将数据划分为逻辑块，逻辑块序号使用 $P _ { i }$ 表示，再在每个逻辑块内以 16 个线程（T0~T15 等）为单位去划分逻辑行，逻辑行序号使用 $R _ { j }$ 表示，每个逻辑行的大小为 128B。将各个逻辑行按顺序存入共享内存中，此时线程束中连续的 16个线程（T0~T15 等）读取的数据量为共享内存一次内存事务的最大数据量（128B）且覆盖了 32 个 bank，满足前文所述的无 bank 冲突的条件，解决了读共享内存的 bank 冲突问题。

接下来在此基础上解决写共享内存的bank冲突问题。图 7 中（b）展示了写共享内存时数据与线程

的排布情况，各个线程从全局内存中读取 8 个 FP16数据，沿着共享内存的连续方向分为两次写入共享

内存，相比沿着跨距方向写入，减少了共享内存写指令的发射数量并提高了共享内存的带宽利用率。对于 T0 和 T1 而言，访问了同一个 bank 的不同存储单元，因此会发生二路 bank 冲突，本研究对逻辑行中的数据进行重排以避免写共享内存 bank 冲突。将图 7 中（b）的数据平均划分为左部分和右部分，将左部分和右部分的线程以两个为一组划分分组。图7 中（c）展示了划分分组的结果，如 T0 和 T16 被划分到一个分组中，组内序号使用 $G _ { k }$ 表示。根据公式（1）执行异或操作，线程能够交错排布以避免写共享内存 bank 冲突：

$$
N _ {s} = G _ {k} \oplus \left(P _ {i} \bmod 2\right) \tag {1}
$$

其中 $N _ { s }$ 为数据和线程组成的方格在分组内的新序号。各个线程都执行上述异或操作，得到的结果如图 7 中（d）所示，可以看出连续的线程在两个逻辑

块中交错排布，线程束中连续的 16 个线程（T0~T15等）写入共享内存的数据量为共享内存一次内存事务的最大数据量（128B）且覆盖了 32 个 bank，满足前文所述的无 bank 冲突的条件，解决了写共享内存的 bank 冲突问题。

# 3.3 数据写回优化策略

向量化访存是指在并行计算中，线程访问连续的内存位置时，通过一次操作处理多个数据元素，以减少内存访问次数，提高数据吞吐率[27]。移植后

的 CUTLASS-Sparse 待写回全局内存的数据的数据排布不是最优排布，本研究使用数据聚集策略以最优化数据排布。如图 10 中数据聚集操作执行前所示，各个线程待写回全局内存的数据呈现出分散分布的状态（全填充或半填充），这种非连续的布局无法使用向量化写回，需要多次非连续的内存访问才能完成数据写回，内存带宽利用率低。

![](images/275a11fbb4f456f6992b9d613422c8c98691eb167f6bfb282ea16366d32ee9be.jpg)  
图 10 数据聚集策略的设计  
Fig.10 The design of data gathering strategy

如图 10 中执行数据聚集操作后所示，各个分散的数据被写入共享内存以执行聚集操作，使得待写回的数据排布重排为全局写回的最优布局，通过一次低延迟的共享内存额外聚集操作，换取更高带宽的全局内存写回。数据聚集操作执行后，各个线程待写回的数据在共享内存中连续排布，各个线程读取共享内存中连续的多个数据，利用向量化写回方式将待写回的数据向量化写回全局内存，提高了数据写回的性能。

在共享内存数据重排算法和数据流水线优化中，写入数据至共享内存时，本研究使用国产加速器内嵌汇编指令实现数据的写入；读取共享内存数据和 Tensor Core 计算时，本研究使用编译器提供的builtin 接口实现共享内存数据读取和数据计算，由编译器自动推导最优的指令流水排布。在数据写回优化中，写入数据至共享内存、读取共享内存数据和写回结果数据至全局内存由内核级的编译自动实

现优化。

在将三种优化方法加入到 CUTLASS-Sparse 模板库的过程中，需要逐层重构移植后的模板库的代码逻辑和数据索引逻辑，使得三种优化方法能够满足各种情况（线程模型设置、数据类型和主序方向设置、内核组件拼接）下的正确性要求。因此，三种优化方法既能够在国产加速器上高效实现，又能够使得优化后的 CUTLASS-Sparse 满足用户定制化的需求。

# 4.3.2 同平台 SPARSE 数学库对比实验

对于单精度 FP32 数据类型，移植与优化后的CUTLASS-Sparse 相 较 于 国 产 加 速 器 平 台 的SPARSE 数学库的性能加速比如图 12 所示，横坐标为 数 据 集 序 号 ， 纵 坐 标 为 移 植 与 优 化 后 的CUTLASS-Sparse 性能相较于 SPARSE 数学库性能的加速比。移植与优化后的 CUTLASS-Sparse 在各个数据集上的性能均高于 SPARSE 数学库的性能，在国产加速器 K 型号上，平均为 SPARSE 数学库性能的 2.36 倍；在国产加速器 B 型号上，平均为SPARSE 数学库性能的 3.09 倍。实验验证了移植与优化后的 CUTLASS-Sparse 能够在本研究所面向的某系列国产加速器的不同型号上实现适配并保持高

性能表现。

移植与优化后的 CUTLASS-Sparse 性能显著高于 SPARSE 数学库性能的重要原因是 Tensor Core 相较于通用计算核心拥有显著的性能优势，其能够在单次执行中并行完成多次乘累加操作，例如对于规模为 $1 6 \times 8$ 和 $8 \times 1 6$ 的矩阵乘法，基于通用计算核心方式完成该运算需要数十至数百条乘累加指令，而基于Tensor Core方式仅需一条专用指令即可完成该运算，大幅提高了计算性能。

# 4.3.3 NVIDIA GPU L20 对比实验

图 13 给出了国产加速器 K 型号上移植与优化后的 CUTLASS-Sparse 与 NVIDIA GPU L20 上CUTLASS-Sparse 原库的性能对比结果，以 GPU L20性能为基准（ $1 0 0 \%$ ），纵坐标表示国产加速器 K 型号性能达到 GPU L20 性能的百分比。对于 TF32 数据类型，移植与优化后的 CUTLASS-Sparse 在国产加速器K型号上的性能平均达到GPU L20上原库性能的 $7 6 \%$ 。对于 FP16 数据类型（FP32 写回和 FP16写回），移植与优化后的 CUTLASS-Sparse 在国产加速器 K 型号上的性能平均达到 GPU L20 上原库

（FP32 写回和 FP16 写回）性能的 $6 1 \%$ 和 $6 0 \%$ 。

![](images/ba3e32d3f3783452cc203f557402f62489e3983aca870c7e342f82a3ee9a3e77.jpg)  
图 13 国产加速器 K 型号相较于 GPU L20 的性能百分比  
Fig.13 The performance percentage of domestic accelerator K compared to the GPU L20

关于国产加速器K型号与GPU L20性能差异的原因，主要表现在 L2 Cache 容量的显著差距，GPUL20 的 L2 Cache 容量为 96MB，而国产加速器 K 型号的 L2 Cache 容量仅为 8MB，两者存在高达 12 倍的容量差距，导致国产加速器 K型号的数据读写速度显著低于 GPU L20 的数据读写速度。因此，在此硬件差距情况下，国产加速器 K 型号相较于 GPUL20 的性能表现已符合预期范围。

# 5 结束语

本文实现了 CUTLASS-Sparse 从 NVIDIA GPU到国产加速器的跨平台移植，并针对国产加速器的硬件特性对移植后的 CUTLASS-Sparse 进行性能优化，优化方法包括共享内存数据排布优化、数据流水线优化和数据写回优化。通过消融实验、同平台数学库对比实验及竞品平台对比实验，表明所提出的三种优化方法对移植后的 CUTLASS-Sparse 的性能提升均显著有效，移植优化后的性能显著高于同平台 SPARSE 数学库的性能，且能够接近 GPU L20

上原库的性能水平，充分体现了移植与优化工作的成效。在未来，计划对 CUTLASS-Sparse 中的线程块重排算法进行优化，以提高 L2 Cache 的命中率；还计划实现 CUTLASS-Sparse 与常用激活函数（如ReLu 等）算子的融合，以减少 CUTLASS-Sparse 与激活函数算子间数据传输的开销。
